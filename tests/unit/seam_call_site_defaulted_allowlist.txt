# Allowlist: defaulted parameters `run.py` does not pass at a stage call site

Read by `tests/unit/test_seam_stage_call_arity.py` (`PartFour`). One entry per
line:

    <module> <parameter> :: <one-line reason>

`<module>` is the dotted stage module, `<parameter>` is the parameter name. The
reason is mandatory and must be specific to *that* parameter at *that* call site
- a reason that would fit any entry is not a reason.

**Why this file exists.** A stage parameter with **no default** is caught by
`inspect.Signature.bind`: omitting it is a `TypeError`. A parameter **with** a
default is invisible to `bind`, because omitting it is legal Python and the
stage simply receives the default. Every default in this codebase is `None`, an
empty container, or a small constant, and for a stage that means one specific
thing: *nobody chose this*. Whether that is a refusal, a documented fallback, or
a silent wrong answer is decided inside the stage body, per parameter, forever.

So an omission is not automatically a defect - plenty of these are deliberate -
but an omission that is **not** written down here is one nobody has looked at.
That is the whole contract: this file is the list of omissions somebody has
actually considered.

**What it is NOT.** It is not permission to omit anything. Adding an entry is a
claim that the omission is benign *and why*; removing the argument's default
would make a stage refuse loudly instead, which is often the better fix and is
not this file's business. Every entry below was read against the stage body, not
inferred from its name.

**How to change it.** Add the line in the same commit as whatever introduced the
omission. `PartFour` fails on a new omission with no entry, so the obligation is
mechanical. If you delete a call-site argument, delete the entry in the same
commit or `PartFour` fails on a now-stale entry.

**`CALL-SITE-LINE` notes.** The line numbers are where `run.py` calls the stage
as of round 12 Phase 3. They are recorded per entry because an omission is a
fact about a *call site*, not about a signature: the same stage called from two
places can legitimately pass a parameter at one and not at the other.

**`omissions.md` and this file are the same list.** `PartFour` derives the
omissions from `run.py` and compares them to this file, so the two cannot
diverge; `pa-artifacts/round12/omissions.md` states the counting rule that
decides which of the derived set are defects and which are decisions, and names
the six that were fixed. A parameter that appears in neither this file nor
`omissions.md` is a defect this file exists to catch.
